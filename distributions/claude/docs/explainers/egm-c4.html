Orchestration

Every round starts from files, not from the conversation

The orchestrator never drafts, judges findings or writes code. It sends a brief of file paths to a fresh subagent and checks what changed on disk.

The orchestrator writes

  • docs/architecture/c4-tasks.md the ledger
  • decisions/<stem>.answers.md append-only, your words verbatim
  • the **Status:** line Draft → Approved → Implemented
  • replacement text you approved applied verbatim
  • gate decisions in review reports marked Status: resolved

Round subagents write

  • decisions/<stem>.tree.md grill rounds only
  • c1-context.md · c2-containers.md · c3-<container>.md
  • c4-build-plan.md · slices/NN-<slice>.md
  • GLOSSARY.md · docs/adr/
  • source code C4 step only, on slice branches

Level loop

C1, C2, C3 and the build plan all pass the same six gates

C2 lists each container as C3: required or C3: skip (reason). Only required containers get a C3 loop. If C2 is approved again, the C3 tasks are reconciled with the new table.

Grilling

Grilling comes first: no level is drafted while a question is open

A skipped question becomes deferred and lands in the draft's Open Questions. When a round reports an empty frontier, you confirm the shared understanding or add topics for another round.

Goldfish review

Isolated reviewers check each document against the C4 standard

The review runs through egm-review-loop in delegated mode. Each loop round writes goldfish_review_report.<RunId>.round-<n>.md in the scope's review folder. A fresh resolve round prepares fixes and stops before the gate. You decide each finding; the orchestrator applies approved text verbatim.

C4 code step

Code arrives in slices, each merged, verified and reviewed by fresh subagents
