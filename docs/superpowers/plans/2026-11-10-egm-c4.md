# EGM C4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `egm-c4` orchestrator skill that takes a greenfield project through C1, C2 and C3 documents with grilling and Goldfish review, then builds it in test-first slices, and remove `egm-brainstorm` and `egm-draft`.

**Architecture:** `skills/egm-c4/SKILL.md` is a thin orchestrator. It reads a task ledger, dispatches every round to a fresh subagent with a brief built from `references/rounds.md`, validates the round result against `references/round-result.schema.json`, records user answers, and updates the ledger. Level content lives in reference playbooks that only the relevant round loads. Review reuses `egm-review-loop` with a new delegated resolution mode.

**Tech Stack:** Markdown skill prompts, JSON schema, YAML scenario files, Python 3.10+ with pytest 9.0.3 and PyYAML 6.0.3 for structural tests. No new dependencies.

**Spec:** `docs/designs/c4.md`. Read it before every task. Where this plan is silent, the spec decides.

## Review Focus

1. **Free-form answers to a grilling round.** A user replies in prose instead of per number. The orchestrator maps each part to a question number, asks only about parts it cannot map, and never invents an answer. Pinned in Task 4.
2. **Hand-edited or malformed ledger.** An unknown status, a missing column or a dangling dependency. The orchestrator stops, shows the bad rows, and does not rewrite the file until the user fixes or confirms. Pinned in Task 2.
3. **`/egm-c4` in a repository that already has source code.** The orchestrator says the flow is for greenfield work and asks before continuing; existing files are never added to allowed paths implicitly. Pinned in Task 4.
4. **A document round writes outside its declared outputs.** The orchestrator path-checks after every round, not only code rounds, and adds a `fix` or `revise` task for violations. Pinned in Task 4.
5. **Harness without a subagent tool.** The orchestrator stops and says that rounds need fresh subagents; it never runs a round inline. Pinned in Task 4.

RESULT_FIELDS = {"task_id", "outcome", "files_written", "questions",

def test_round_result_schema_shape() -> None:
  s = schema()

  assert s["additionalProperties"] is False
  assert set(s["required"]) == RESULT_FIELDS == set(s["properties"])
  props = s["properties"]

  assert set(props["contradictions"]["items"]["required"]) == CONTRADICTION_FIELDS
  assert set(props["new_tasks"]["items"]["required"]) == NEW_TASK_FIELDS


def test_round_examples_match_schema() -> None:

    assert all(set(t) == NEW_TASK_FIELDS for t in result["new_tasks"])
